# Статьи памятников: включение и откат

Редактирование остаётся в Django admin. Поле `article` используется только на
отдельной странице памятника. Попап карты и `description` не изменены.

## Быстро вернуть прежний вид

В `src/config.jsx` установите:

```js
export const ENABLE_MONUMENT_ARTICLES = false;
```

Пересоберите и разверните фронтенд (локальный dev-сервер обновится автоматически).
Вернутся старое описание и отдельная галерея. Статьи и изображения в Django
останутся сохранены. Для повторного включения установите `true`.

При включённой функции пустая статья и `Lorem ipsum` также используют прежний вид.
Для заполненной статьи отдельная нижняя галерея скрыта: фотографии размещает автор
в тексте. Сведения о памятнике и источники остаются на странице.

## Полностью убрать реализацию

Перед работой репозиторий был чист. Изменены только `src/config.jsx`,
`src/components/MonumentDetailsCenter.jsx`, `package.json`, `package-lock.json`.
Новые файлы: `src/components/article/`, `src/styles/MonumentArticle.css` и этот документ.
Верните изменения этих четырёх существовавших файлов через Git diff/редактор,
удалите перечисленные новые файлы и выполните `npm install`.
Если после этого изменения делались вручную, отменяйте только изменения статьи,
а не восстанавливайте файлы целиком. Бэкенд откатывать не требуется.

## Проверка

`npm run test:article` и `npm run build`.
Старый `App.test.js` относится к шаблону Create React App и не проверяет текущий
интерфейс; общий запуск тестов также останавливается на ESM-импорте react-leaflet.
На странице памятника проверить порядок текста, одиночные фотографии, две
независимые карусели, подписи, стрелки, свайп и увеличение фотографий.
HTML очищается на клиенте; это не заменяет серверную проверку при сохранении.
