# Как разобраться в коде проекта

Начните с `src/index.js`, затем откройте `src/App.jsx`. Первый файл запускает приложение, второй связывает адреса со страницами. В начале каждого исходного файла теперь есть пояснение его назначения, а рядом со сложными участками — объяснения логики.

## Где что менять

| Что нужно изменить | Где искать |
| --- | --- |
| Адрес сервера с памятниками и источниками | `src/config.jsx`, значение `API_BASE_URL` |
| Адреса страниц | `src/App.jsx`, элементы `Route` |
| Верхнее меню и логотип | `src/components/Header.jsx` и `src/styles/Header.css` |
| Нижнее меню и логотипы музеев | `src/components/Footer.jsx` и `src/styles/Footer.css` |
| Высоту шапки и подвала, общий фон | `src/styles/Theme.css`; расположение блоков — `src/styles/App.css` |
| Приветствие, кнопки входа на карту | `src/pages/StartPage.jsx` и `src/styles/StartPage.css` |
| Центр карты, приближение, границы перемещения | `src/pages/MapPage.jsx`: `MapContainer` и `maxBounds` |
| Цвет и размер точек | `markerIcon` в `MapPage.jsx`; подсветка — в `src/styles/MapPage.css` |
| Правила отбора точек | `filteredMarkers` в `MapPage.jsx` |
| Загрузку памятников и выбор фильтров | `src/components/useMonumentsData.jsx` |
| Переключение вкладок и раскрытие фильтров | `src/pages/FilterPopupPage.jsx` |
| Галочки типов, датировок и дополнительных категорий | `TypeDropdown.jsx`, `DatingDropdown.jsx`, `CustomCategoryDropdown.jsx` в `src/components` |
| Поля описания на карте | `src/components/PopupContent.jsx` |
| Поля отдельной страницы памятника | `src/components/MonumentDetailsCenter.jsx` |
| Поиск памятников по названию | `src/pages/MonumentsListPage.jsx` |
| Загрузку и группировку источников | `src/components/useBibliographyData.jsx` |
| Поиск, раскрытие подразделов и сортировку источников | `src/components/BibliographyList.jsx` |
| Тексты о проекте, авторах и инструкцию | `AboutProjectPage.jsx`, `AboutAuthorsPage.jsx`, `HowToUsePage.jsx` в `src/pages` |
| Название вкладки браузера и описание сайта | `public/index.html`: `title` и `meta name="description"` |

Названия и описания самих памятников, категории и источники приходят с сервера. Для изменения содержимого этих записей нужно редактировать данные на сервере. В этом проекте меняется то, как они загружаются и показываются.

## Как движутся данные

1. Пользователь открывает `/map`. `App` выбирает `MapPage`.
2. `MapPage` вызывает `useMonumentsData`. Хук отправляет запрос `/api/monuments/` на сервер из `config.jsx`.
3. Ответ сохраняется в состоянии `monuments`. React обновляет экран, на карте появляются точки.
4. Нажатие галочки вызывает функцию `handle...Change`. Она изменяет массив выбранных значений.
5. `filteredMarkers` оставляет подходящие памятники. Внутри одной группы достаточно одного совпадения, между заполненными группами нужны совпадения во всех.
6. Нажатие точки сохраняет памятник в `selectedMarkerInfo`. Панель получает этот объект и показывает `PopupContent`.
7. Ссылка `/monument/12` открывает `MonumentDetailsPage`. Она извлекает `12` из адреса и передаёт в `MonumentDetailsCenter`, который отдельно запрашивает `/api/monuments/12/`.

Обычный объект памятника содержит `id`, `name`, `latitude`, `longitude`, `description` и другие поля, используемые в карточках. Поля `dating`, `classification_category`, `custom_category`, `images`, `organizations` и `research_years` используются как массивы. `content` и `sources` используются как объекты вида «название: ссылка». Если сервер меняет формат поля, соответствующие места отображения тоже нужно проверить.

## Небольшой словарь React и JavaScript

| Запись | Что означает |
| --- | --- |
| `import ... from ...` | Подключить компонент, функцию, картинку или стили из другого файла или библиотеки. |
| `export default` | Указать главное значение, которое другой файл может импортировать. Имя при импорте может отличаться. |
| Компонент | Функция, описывающая часть интерфейса. Например, `Header` — шапку. |
| JSX | Разметка внутри JavaScript, похожая на HTML. В фигурных скобках можно использовать значения и выражения. |
| `className="..."` | Назначить элементу CSS-класс. В CSS его выбирают через `.имя`. |
| Props | Данные и функции, переданные компоненту родителем, например `<MonumentDetailsCenter id={id} />`. |
| `const [value, setValue] = useState(...)` | Хранить значение между обновлениями экрана. `setValue` меняет значение и запускает обновление. |
| `useEffect(..., [])` | Выполнить действие после появления компонента. В режиме разработки StrictMode возможен дополнительный запуск. |
| `useEffect(..., [id])` | Выполнить действие после появления компонента и повторить при изменении `id`. |
| `onClick`, `onChange` | Функции, вызываемые при нажатии и изменении поля. |
| `event.target.value` | Значение поля, вызвавшего событие. |
| `event.target.checked` | Установлена ли галочка. |
| `items.map(...)` | Превратить каждый элемент массива в другое значение, например в строку списка. |
| `items.filter(...)` | Создать новый массив только с элементами, прошедшими проверку. |
| `items.some(...)` | Проверить, подходит ли хотя бы один элемент. |
| `items.includes(value)` | Проверить, есть ли значение в массиве. |
| `items.join(', ')` | Соединить элементы массива в одну строку через запятую и пробел. |
| `...items` или `...object` | Скопировать элементы массива или свойства объекта в новый массив/объект. |
| `condition && <Block />` | Показать блок, если условие истинно. |
| `condition ? a : b` | Выбрать `a`, если условие истинно, иначе `b`. |
| `object?.id` | Прочитать `id`, только если объект существует; иначе получить `undefined`. |
| `key={item.id}` | Помочь React отличать элементы списка при обновлении. Ключ должен быть устойчивым и уникальным среди соседей. |
| `async` и `await` | Описать ожидание ответа сервера без остановки работы интерфейса. |
| `try/catch` | Попробовать выполнить действие и обработать возникшую ошибку. |

Обычный комментарий JavaScript начинается с `//` или заключён в `/* ... */`. Внутри JSX используется `{/* ... */}`. Такой комментарий ставится между элементами внутри общей обёртки, а не отдельным элементом перед корнем возвращаемой разметки.

## Как читать стили

Все наши стили подключаются через `src/styles/index.css`. Подробная карта файлов и простые правила редактирования находятся в [src/styles/README.md](src/styles/README.md). Общие цвета и размеры задаются в `Theme.css`, текстовые страницы используют `ReadingPages.css`, карта — `MapPage.css` и `MapPanel.css`, карточки — `MonumentContent.css`, фотографии — `Gallery.css`.

Эти стили не изолированы автоматически: общий класс `.link`, например, оформляет ссылки на нескольких страницах. Сначала найдите `className` нужного элемента, затем его правило в соответствующем файле. Общие блоки описаны один раз, отличия для небольших экранов находятся в `@media` внизу файла.

`padding` задаёт внутренний отступ, `margin` — внешний. Два значения означают «сверху/снизу, слева/справа», четыре — «сверху, справа, снизу, слева». `width` и `height` задают размеры, `max-width` ограничивает ширину сверху. `box-sizing: border-box` включает рамку и внутренние отступы в заданный размер.

`display: flex` помогает расположить элементы в ряд или колонку. `flex-direction: column` выбирает колонку. `display: grid` создаёт сетку, её колонки задаёт `grid-template-columns`. `position: fixed` закрепляет блок относительно окна в обычной ситуации; `absolute` размещает его относительно ближайшего подходящего содержащего блока.

`1vw` — 1% ширины окна, `1vh` — 1% высоты; `dvh` учитывает изменение доступной высоты окна на телефоне. `calc(...)` вычисляет размер, `clamp(минимум, значение, максимум)` ограничивает его снизу и сверху. `env(safe-area-inset-bottom)` помогает оставить место у нижнего края экрана устройства.

`@media (max-width: 768px)` применяется при ширине окна до 768 пикселей включительно. Если изменение видно на компьютере, но не видно на телефоне, проверьте, нет ли ниже отдельного правила для узкого окна.

## Файлы настроек без комментариев

JSON не разрешает комментарии, поэтому следующие файлы пояснены здесь.

### package.json

- `name`, `version`, `private` — имя пакета, версия и запрет случайной публикации через npm.
- `dependencies` — библиотеки проекта. React отвечает за интерфейс, react-router-dom — за страницы, Leaflet и react-leaflet — за карту, axios — за запросы, react-photo-view — за просмотр фотографий.
- `scripts.start` — команда `npm start`, запуск сервера разработки.
- `scripts.build` — команда `npm run build`, создание готовых файлов в папке `build`.
- `scripts.test` — команда `npm test`, запуск проверок.
- `scripts.eject` — извлечение скрытой конфигурации react-scripts в проект; для обычного изменения страниц не требуется.
- `eslintConfig` — правила автоматической проверки кода.
- `browserslist` — список целевых браузеров, которым сборщик подготавливает JavaScript и CSS.

`package-lock.json` автоматически фиксирует конкретные версии библиотек и их зависимостей. Это сгенерированный файл; пояснения и настройки приложения туда не добавляют.

### public/manifest.json

- `short_name` и `name` — короткое и полное название при добавлении сайта на устройство. Сейчас здесь остались названия шаблона React.
- `icons` — значки: `src` указывает файл, `sizes` — размер, `type` — формат.
- `start_url` — адрес открытия установленного приложения.
- `display: standalone` — запрос показа приложения отдельным окном без обычного интерфейса браузера, если устройство это поддерживает.
- `theme_color` и `background_color` — цвет оформления и фон запуска.

`public/robots.txt` даёт указания поисковым роботам: `User-agent: *` относится ко всем роботам, пустое `Disallow:` не запрещает обход страниц. Это не ограничение доступа к сайту.

`Dockerfile` описывает сборку образа, `docker-compose.yml` — запуск контейнера и порты. Сейчас контейнер запускает сервер разработки через `npm start`, хотя перед этим создаётся папка `build`.

Картинки в `src/assets`, шрифты в `src/fonts`, содержимое `node_modules` и собранная папка `build` не являются местом для комментариев к исходному коду. Зависимости устанавливаются отдельно, а `build` заново создаётся сборкой.

## Что полезно знать перед правками

- Неиспользуемые `src/App.css` и `CreamBackground.css` удалены. Общий каркас находится в `src/styles/App.css`.
- Прежние слои `DesktopSizing.css` и `ModernTheme.css` объединены со стилями соответствующих элементов. Новые исправления нужно вносить в эти правила, а не добавлять очередной слой переопределений.
- `sortByPublicationDateDesc` фактически сортирует даты по возрастанию. Записи без даты идут первыми.
- `Array.sort` меняет сам массив. В списке памятников он применяется непосредственно к `monuments`.
- В `App.test.js` остался тест на надпись `learn react`, которой на сайте уже нет. Перед использованием этой проверки её нужно обновить под настоящий интерфейс.
- Заготовки словаря, статей и новостей имеют маршруты, но ссылки на них закомментированы в верхнем меню. `News.jsx` сейчас запрашивает памятники, а не новости.
- В полной карточке ошибка запроса выводится в консоль, но отдельное сообщение об ошибке не показано: остаётся `Loading...`.

После изменения исходников выполните `npm run build`: эта команда помогает обнаружить синтаксические ошибки и проблемы импортов. Для проверки поведения запустите `npm start`, откройте изменённую страницу и проверьте её на широком и узком окне. Для карты, памятников и источников также должен работать сервер API.
