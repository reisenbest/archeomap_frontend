# Как устроены стили

Начните с `index.css`: он перечисляет все наши CSS-файлы в порядке подключения. В приложение он импортируется один раз, в `App.jsx`. В компонентах остаются только стили сторонних библиотек Leaflet и PhotoView.

В каждом файле сначала идут обычные правила, затем изменения для разных размеров экрана. Комментарии перед блоками объясняют, какой элемент они оформляют. Одно свойство записано на одной строке.

## Где что менять

| Файл | За что отвечает |
| --- | --- |
| `Theme.css` | Общие цвета, высоты шапки и подвала, отступы, обычный шрифт |
| `Base.css` | Подключение шрифтов, фон страницы, выделенный текст, фокус и полосы прокрутки |
| `App.css` | Расположение шапки, подвала и основной области |
| `Header.css` | Верхнее меню, название сайта, логотип и кнопка компактного меню |
| `Footer.css` | Логотипы музеев и нижнее меню |
| `ReadingPages.css` | Общая рамка текстовых страниц, поиск, списки, авторы и инструкция |
| `StartPage.css` | Приветственная страница и её фоновая фотография |
| `MapPage.css` | Размеры карты, маркеры, окно Leaflet и сворачивание боковой панели |
| `MapPanel.css` | Вкладки панели карты, фильтры, галочки и мобильное окно |
| `MonumentContent.css` | Название, описание и метки памятника; подсказка до выбора точки |
| `Gallery.css` | Миниатюры, открытая фотография и подписи |
| `Typography.css` | Пиксельный шрифт основных заголовков и названий памятников |
| `Accessibility.css` | Отключение лишних анимаций по системной настройке пользователя |

`ReadingPages.css` объединяет оформление списка памятников, библиографии, страниц проекта, авторов, инструкции и отдельного памятника. Общая рамка этих страниц описана один раз. Отличия отмечены комментариями: например, портреты авторов, подразделы библиографии и размеры иллюстраций инструкции.

## Как вносить изменения

1. Найдите нужный элемент в таблице выше, затем его `className` в соответствующем CSS-файле.
2. Изменяйте существующее правило. Если значение должно отличаться только на телефоне, меняйте его в подходящем `@media` внизу этого же файла.
3. Общие цвета и размеры меняйте в `Theme.css`. Например, `--header-height` одновременно управляет высотой шапки и отступом содержимого под ней.
4. Проверьте страницу на широком и узком экране, включая открытые меню, фильтры и фотографии.
5. Выполните `npm run build`, чтобы проверить корректность CSS и импортов.

Не создавайте отдельный файл «исправлений поверх всего». Прежние `DesktopSizing.css` и `ModernTheme.css` разобраны: их действующие правила находятся рядом с элементами, к которым относятся.

## Что означают основные записи

- `.header` — элемент с `className="header"`.
- `.header a` — ссылка внутри такого элемента.
- `.nav-link:hover` — ссылка, на которую навели указатель.
- `.nav-link.active` — ссылка с дополнительным классом `active`.
- `var(--paper)` — значение переменной из `Theme.css`.
- `padding` — отступ внутри элемента; `margin` — снаружи.
- `@media (max-width: 600px)` — правило для окна шириной до 600 пикселей включительно.

Важен не только порядок правил, но и точность селектора. Например, `.info-text .checkbox-item label` уточняет общее оформление `.checkbox-item label` именно для мобильной панели. Такие уточнения сохранены там, где они нужны для текущего вида сайта.

## Границы адаптивной вёрстки

| Ширина окна | Изменение |
| --- | --- |
| До 600 px | Компактные размеры шапки, подвала, отступов и портретов |
| До 768 px | Дополнительные настройки оболочки страницы памятника |
| До 1000 px | Мобильная панель карты вместо постоянной боковой панели |
| До 1028 px | Компактное нижнее меню |
| До 1100 px | Компактное верхнее меню |

Границы сохранены из существующего оформления. Они различаются, потому что меню и карта перестают помещаться при разной ширине.

`Typography.css` и `Accessibility.css` подключаются последними намеренно: первый задаёт общий шрифт заголовков после размеров на страницах, второй учитывает настройку уменьшения движения.

Что проверялось при объединении стилей и какие ограничения есть у проверки: [CHECKS.md](CHECKS.md).
